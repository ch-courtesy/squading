## 관찰 근거

설계 전반의 공유 코어, 어댑터 계약, 선택 규칙과 실패 처리 방향은 타당하지만 구현 계획으로 전환하기에는 다음 공백이 있다.

- 고정 틱, 단일 시드 RNG, 안정적인 처리 순서와 렌더 스냅샷 하위 타입이 없다.
- 이펙트 수명 주기의 소유자가 불분명하고 수동 조작이 동일 tick 비교와 충돌한다.
- 렌더러별 동적 import, 등가 프레이밍, 엔진마다 다른 드로우콜의 비교 한계가 필요하다.
- 메모리 증가, 전환 누수, 품질 저하 뒤 회복의 수치와 측정 창이 없다.
- 에셋 출처·라이선스와 완성 게임 제작량 외삽이 없다.
- 60~90초 벤치마크에는 승패, 재시작, 조작 안내가 없어 Track 1 제출 안전망이 부족하다.
- 기반 도구·배포 단계와 단계별 실행 가능한 완료 기준이 없다.

## 수정 브리프

1. 고정 틱, 단일 시드 RNG, 전체 렌더 스냅샷 타입, 코어 소유 이펙트 수명을 정의한다.
2. 자동 벤치마크와 수동 플레이를 분리한다.
3. 동적 import, 드로우콜 한계, 등가 프레이밍을 정의한다.
4. 메모리·품질 회복 측정 창, 전원 탈락 규칙과 선택 점수 정의를 추가한다.
5. 에셋 라이선스 정책과 제작량 외삽표를 요구한다.
6. 생존 성공·전멸 실패·재시작·조작 안내와 렌더러 타임박스를 추가한다.
7. 기반 단계, 단계별 완료 기준과 Codex 기록 갱신을 구현 순서에 넣는다.

성장 선택과 캠페인은 계속 제외하고, 승패는 생존 시간 도달·전멸·재시작 이상으로 확장하지 않는다.

## 재판정

- 판정: `APPROVED`
- 근거: 하위 렌더 타입, 0~5 단계별 완료 기준, 수치화된 선택 규칙, 자동·수동 모드 분리와 수정 브리프 7개 항목을 모두 확인했다.
- 비차단 조언: `structure-signal`을 `rescue-signal`로 명확히 하고, 고정 스텝 루프에 프레임당 최대 5틱과 초과 표본 무효 처리를 넣는다.

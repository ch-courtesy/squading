# Claude CLI Advisor 전역 스킬 설계

## 목표

Codex가 구현 작업을 수행할 때 별도의 Claude Advisor에게 요구사항 분석과 결과 검증을 맡길 수 있는 개인 전역 `advisor` 스킬을 만든다. Advisor와의 통신에는 `claude -p`를 사용하고, 기본 모델은 `fable`, 사용량 초과 또는 이용 불가 시 대체 모델은 `opus`로 한다.

## 설치 범위

- 설치 경로: `/Users/courtesy/.codex/skills/advisor`
- 적용 범위: 모든 Codex 프로젝트에서 사용하는 개인 전역 스킬
- 호출 예시: `$advisor <과제>` 또는 자연어로 Advisor 감독 요청

## 구성

```text
advisor/
├── SKILL.md
├── agents/
│   └── openai.yaml
└── scripts/
    └── advisor.sh
```

- `SKILL.md`: Worker와 Advisor의 역할, 상태 태그, 질의·구현·검증 반복, 실패 복구 규칙을 정의한다.
- `agents/openai.yaml`: 스킬 목록에 표시할 이름, 설명, 기본 프롬프트를 정의한다.
- `scripts/advisor.sh`: Claude CLI 호출, 세션 생성·재개, 모델 선택, 오류 분류 및 대체 모델 재시도를 담당한다.

## 역할

### Worker

호출된 Codex 세션이 Worker 역할을 맡는다.

- 사용자 요청과 저장소 컨텍스트를 Advisor에게 전달한다.
- Advisor의 브리프에 따라 파일을 수정한다.
- 검증 명령을 실행하고 전체 결과와 `git diff`를 Advisor에게 전달한다.
- Advisor가 승인한 뒤에만 완료를 보고한다.
- 사용자가 명시적으로 요청한 경우에만 커밋한다.

### Advisor

Claude CLI로 실행되는 별도 세션이 Advisor 역할을 맡는다.

- 요구사항을 분석하고 구현 브리프를 작성한다.
- 필요한 사용자 질문을 작성한다.
- Worker가 전달한 diff와 검증 결과를 평가한다.
- 구현 노동, 파일 수정 및 커밋은 수행하지 않는다.
- 저장소 탐색에는 `Read`, `Grep`, `Glob`만 사용한다.

## 상태 계약

Advisor의 모든 응답 첫 줄은 다음 상태 중 하나여야 한다.

- `BRIEF`: 구현 목표, 대상 파일, 컨벤션, 함정, 검증 명령을 제공한다.
- `QUESTION`: 사용자 결정이 필요한 질문을 제공한다.
- `SKIP`: 감독 비용이 작업 비용보다 큰 단순 작업이므로 Worker 직접 처리를 허용한다.
- `APPROVED`: 요구사항과 검증 조건을 충족했음을 승인한다.
- `REVISE`: 발견한 문제와 다음 수정 브리프를 제공한다.
- `ESCALATE`: 반복 실패 또는 요구사항 충돌을 사용자에게 이관한다.

상태 태그가 없거나 알 수 없는 태그가 반환되면 프로토콜 오류로 처리하고 동일 세션에 형식 준수를 한 번 요청한다. 다시 실패하면 사용자에게 오류를 보고한다.

## 호출과 세션

### 최초 호출

`advisor.sh start`가 다음 정보를 포함한 프롬프트로 Claude를 실행한다.

- 사용자 요청 원문
- Worker가 확인한 파일, 프로젝트 규약, 제약 및 완료 기준
- Advisor 역할과 상태 계약

Claude는 JSON 형식으로 응답하며, 래퍼는 응답 본문과 `session_id`를 반환한다.

### 후속 호출

`advisor.sh resume <session-id>`가 동일한 Claude 세션을 재개한다. Worker는 사용자 답변, 구현 중 판단 요청 또는 완료 보고를 전달한다.

### 세션 복구

세션 재개에 실패하면 Worker는 사용자 요청, 최신 브리프, 완료 보고, 이전 판정과 라운드 횟수를 압축해 새로운 Advisor 세션을 시작한다. 복구 사실을 기록하고 검증 절차를 계속한다.

## 모델 선택과 대체

1. 호출에서 모델을 명시하면 해당 모델을 우선 사용한다.
2. 모델을 명시하지 않으면 `fable`을 사용한다.
3. `fable` 호출이 사용량 초과, 모델 이용 불가 또는 과부하로 실패하면 `opus`로 한 번 재시도한다.
4. Claude CLI의 `--fallback-model opus`를 함께 사용하되, CLI가 자동 대체하지 못한 사용량 초과 오류도 래퍼가 감지해 명시적으로 재시도한다.
5. `opus`도 실패하면 stderr와 종료 코드를 보존해 Worker가 사용자에게 보고한다.

명시적으로 선택한 모델이 실패했을 때는 사용자 의도를 보존하기 위해 자동으로 다른 모델로 바꾸지 않는다. 단, 사용자가 `fable`을 명시했거나 기본값이 적용된 경우에는 `opus` 대체를 허용한다.

## 권한과 안전

- Claude CLI는 비대화식 `-p` 모드와 계획 권한 모드로 실행한다.
- Advisor 도구는 `Read`, `Grep`, `Glob`으로 제한한다.
- `Bash`, `Edit`, `Write`, 커밋, 푸시 및 외부 상태 변경 권한을 제공하지 않는다.
- Worker가 검증 명령과 `git diff`를 실행하고 결과를 Advisor 메시지로 전달한다.
- 프롬프트나 결과에 비밀정보, 인증 토큰 또는 불필요한 개인정보를 포함하지 않는다.
- Advisor는 제안과 판정만 수행하며 최종 실행 권한은 Worker와 사용자에게 남긴다.

## 작업 흐름

1. Worker가 컨텍스트를 수집하고 Advisor 세션을 시작한다.
2. Advisor가 `QUESTION`, `SKIP` 또는 `BRIEF`를 반환한다.
3. `QUESTION`이면 Worker가 사용 가능한 구조화된 UI 질문 도구로 사용자에게 묻고 답을 동일 세션에 전달한다.
4. `BRIEF`이면 Worker가 지시 범위에서 구현하고 검증 명령을 실행한다.
5. Worker가 변경 파일, `git diff`, 명령과 전체 결과를 Advisor에게 전달한다.
6. Advisor가 `APPROVED`, `REVISE` 또는 `ESCALATE`를 반환한다.
7. `REVISE`이면 최대 세 라운드까지 구현과 검증을 반복한다.
8. `APPROVED`이면 Worker가 승인과 검증 근거를 사용자에게 보고한다.
9. 사용자가 커밋을 요청한 경우에만 Worker가 커밋한다.

구조화된 UI 질문 도구가 현재 모드에서 제공되지 않을 때만 일반 텍스트 질문을 사용한다.

## 오류 처리

- Claude CLI 미설치: 실행 경로 확인 결과와 설치 필요 사실을 보고한다.
- 인증 실패: 자동 우회하지 않고 Claude 인증을 요청한다.
- 모델 오류: 모델 대체 규칙에 따라 한 번만 재시도한다.
- 빈 응답 또는 JSON 파싱 실패: 원본 출력을 보존하고 한 번 재시도한다.
- 알 수 없는 상태 태그: 형식 교정 요청 후 반복 실패 시 중단한다.
- Advisor 세션 소실: 새 세션에 압축 컨텍스트를 전달해 복구한다.
- 세 번의 `REVISE` 이후 미승인: `ESCALATE`로 사용자 결정을 요청한다.

## 검증 전략

### 자동 테스트

실제 Claude 사용량을 소비하지 않도록 가짜 `claude` 실행 파일을 사용해 다음을 검증한다.

- 기본 호출이 `--model fable`을 사용한다.
- 기본 호출에 `--fallback-model opus`가 포함된다.
- 사용량 초과 실패 시 `opus`로 정확히 한 번 재시도한다.
- 명시적으로 선택한 비기본 모델은 자동 대체하지 않는다.
- 최초 JSON 응답에서 `session_id`와 결과 본문을 추출한다.
- 후속 호출이 올바른 세션 ID로 `--resume`을 사용한다.
- 실패 시 종료 코드와 stderr가 보존된다.

### 구조 검증

- `skill-creator`의 `quick_validate.py`로 폴더와 YAML frontmatter를 검증한다.
- `agents/openai.yaml`이 `SKILL.md`의 이름, 설명 및 기본 프롬프트와 일치하는지 확인한다.
- `SKILL.md`에 상태 계약, 모델 대체, 권한 제한, 라운드 제한 및 복구 규칙이 모두 존재하는지 확인한다.

### 실제 호출 검증

실제 Claude 호출은 인증, 네트워크 및 사용량을 소비할 수 있으므로 사용자 승인을 받은 뒤 별도 스모크 테스트로 수행한다. 스모크 테스트는 파일 변경이 없는 작은 브리프 요청과 동일 세션 재개까지만 확인한다.

## 완료 기준

- 개인 전역 `advisor` 스킬이 Codex에서 발견된다.
- `claude -p`를 통해 지정 모델로 Advisor 세션을 시작하고 재개할 수 있다.
- 기본 `fable` 호출 실패 시 `opus` 대체가 자동으로 작동한다.
- Advisor가 파일을 수정하거나 커밋할 수 없다.
- Worker와 Advisor가 상태 계약에 따라 승인 또는 사용자 이관까지 반복한다.
- 가짜 CLI 자동 테스트와 스킬 구조 검증이 모두 통과한다.

# Codex를 어떻게 썼나

`docs/codex-usage-log.md`는 작업 단위 기록 623줄이다. 이 문서는 그중 **방식**만 뽑은 요약이다.

## 한 줄 요약

Codex를 **코드를 쓰는 도구**가 아니라 **설계를 판정하는 자리**에 뒀다. 판정 근거는 사람의 직관도 모델의 직관도 아니고 **매번 새로 돌린 측정**이다.

---

## 1. 스펙이 권위이고, 코드는 스펙을 인용한다

규칙은 `docs/superpowers/specs/`에 산다 — 전투 613줄, 캠페인 206줄. 코드 주석은 `§1.11`처럼 조항을 인용하고, 조항이 바뀌면 버전이 오른다.

세션 중 실제로 오른 버전들:

| 조항 | 버전 | 무엇이 바뀌었나 |
|---|---|---|
| §1.4.1 리쉬 교전 | v11 → **v22** | 병사가 각자 싸운다 → 베어링 분산 → 원거리 회피 |
| §1.11 구조 | → **v19** | 조건 넷을 둘로. "사람이 못 느낀다"가 규칙의 결함이었다 |
| §1.13 성장 | → **v2** | 캠페인 4회 → 판마다 리셋 + 카드 레벨 |
| §1.2.1 아군 병종 | v16 → **v20** | 능력치 병종(철회) → 돌격 축 → 화면에 보이게 |

**버전이 오르는 조건은 "더 나은 아이디어"가 아니라 "측정이 현재 조항을 반증한 것"이다.**

## 2. 불변식이 게임을 정의한다

무엇이 재미인지를 문장으로 적고, 그 문장을 봇이 매번 검증한다.

- **I3** 정지 플레이는 전멸한다
- **I8** 순수 도망은 이기지 못한다
- **I10** 한 자리에 눌러앉는 플레이는 이기지 못한다
- **I13** 구조를 포기하면 최종 생존이 3명 이상 손해다

여덟 개 정책 봇(`skilled`, `flees-always`, `camps-in-place`, `tactical-no-input`, `abandons-downed`, `ignores-range` …)이 여덟 시드를 완주한다. **설계 변경은 이 밴드를 통과해야 채택된다.**

이게 실제로 한 일:

- §1.2.1 v16(능력치 근접병)은 `skilled`를 8/8로 두면서 고정 경로를 8/8 → 4/8로 죽였다. **철회.**
- §1.4.1의 자율 회피는 **다섯 가지 형태 전부** I8을 6~8/8로 깼다. **전부 폐기**하고 플레이어 조건부로 다시 설계.
- §1.13 v2는 의도하지 않은 곳을 고쳤다 — 네 배치 동안 알려진 실패로 안고 가던 **I8이 `1/8` → `0/8`로 복구**됐다.

## 3. 8시드로는 부족하다는 것도 측정했다

§1.4.1 v21의 4절 형태는 밴드 8시드에서 I8 `0/8`이었다. **새 16시드에서 `2/16`**이었다.

절을 하나 더 붙여 `0/8` · `0/16`으로 만들었고, 스펙에 적었다 — **이 조항을 만지는 튜닝은 24시드로 다시 잰다.**

## 4. 테스트가 진짜 무는지도 잰다

`scripts/mutate.mjs`가 규칙을 **96가지 방식으로 고의로 망가뜨린다.** "물러나는 대신 달려든다", "레벨 3 카드를 레벨 1처럼 인쇄한다", "구조가 끝나도 아무 소리도 안 낸다" 같은 것들이다.

**96/96 전부 잡힌다.**

이 하네스가 실제로 잡아낸 것: 뮤테이션 목록을 **테스트가 아니라 규칙에서** 뽑도록 규율을 바꾸자, 이전에 "24/24 통과"이던 것이 **5개가 살아남는** 상태로 드러났다. 세 라운드에 걸쳐 다 메웠다.

## 5. 리뷰의 최대 결함 유형

리뷰 20여 라운드에서 압도적으로 많았던 것은 **권위 문서가 아무도 지키지 않는 불변식을 주장하는 것**이었다. 리뷰 두 라운드는 옛 거짓을 고치면서 새 거짓을 만들었다.

그래서 모든 에이전트에게 붙인 상시 지시:

> **참으로 만들지 않은 주장을 쓰지 마라. 참으로 만들 수 없으면, 실제로 그런 상태라고 써라.**

이 README와 스펙에 "아직 틀린 것"이 명시돼 있는 이유다.

## 6. 사람의 보고가 가장 강한 측정이다

하네스가 통과시킨 것을 사람이 반증한 사례들:

| 사람이 한 말 | 하네스가 못 잡은 이유 |
|---|---|
| "각개전투가 되어야 하는데 왜 모두 같이 움직이지" | 밴드는 승패만 잰다. 열다섯이 한 덩어리로 미끄러져도 이긴다 |
| "구조한 느낌이 안 남" | 구조 성공률은 정상이었다. 문제는 **완료 시 렌더 이벤트가 없다는 것** |
| "왜 아직도 근접 무기가 없어" | 시뮬레이션은 완벽했다. `UnitKind`에 값이 없어 **화면에 안 닿았다** |
| "bgm 좀 없나?" | 모든 노드가 돌았다. **55Hz는 노트북 스피커가 재생 못 한다** |
| "너무 어려워짐" | `skilled` 8/8. 사람은 `skilled`가 아니다 |

여기서 **고정 경로 측정**(사람 대리 지표)이라는 도구가 나왔다 — 적응형 정책과 달리, 스크립트로 고정한 카이팅 경로를 재는 것. §1.2.1 v16의 회귀는 이것만 잡았다.

## 7. 실패도 기록한다

- 브라우저 테스트가 **머신 부하를 핀으로 박고 있었다.** 같은 시드가 직렬 실행에선 지고 단독 실행에선 이겼다. 시드 교체는 오답이었고, 24시드에서 0으로 측정된 불변식에 묶어 해결했다.
- 비교 측정 중 `git checkout --`으로 **커밋 안 한 재작성을 날렸다.** 다시 썼다.
- 주석 안의 백틱이 템플릿 리터럴을 끊어 **화면이 검게 나갔다.** 두 번.

# 게임 완성도 감사

## 판정

현재 `prototype/`은 세 렌더러와 결정론 코어를 비교하는 기술 프로토타입이다. OpenAI Game Builders Track 1에 제출할 수 있는 완성 게임으로는 아직 부족하다.

## 직접 확인한 동작

- 선택 화면, 적 수·seed 설정, 조작 안내, 게임 시작, 이동, 분대 전환, 구조, 종료 상태, 재시작, JSON 내보내기는 작동한다.
- Phaser 2D, Three.js 2.5D, Three.js 3D가 같은 snapshot과 결과를 사용한다.
- 로컬 Chrome/WebKit에서 시작·종료·재시작이 작동한다.

## 핵심 차단 문제

### 1. 플레이어 선택이 승패를 바꾸지 않는다

같은 seed에서 2,250 tick까지 입력을 바꿔 비교했다.

| 적 수 | 무입력 | 구조 | 계속 이동 | benchmark 입력 |
|---|---|---|---|---|
| 100 | 75초 승리 | 75초 승리 | 75초 승리 | 75초 승리 |
| 200 | 75초 승리 | 75초 승리 | 75초 승리 | 75초 승리 |
| 300 | tick 2175 전멸 | tick 2200 전멸 | tick 2175 전멸 | tick 2200 전멸 |

이동과 분대 전환은 공격 대상·피해 회피·진형·구조 가능성에 영향을 주지 않는다. 300명 모드 전멸은 60초 이후 일정 간격으로 아군을 강제로 쓰러뜨리는 `applyOverrun()`에 의해 결정된다.

### 2. Vampire Survivors식 성장 루프가 없다

- 처치 경험치와 레벨업이 없다.
- 무기·업그레이드 선택이 없다.
- 빌드 조합과 런별 변주가 없다.
- 강해지는 체감과 보상 선택이 없다.

### 3. First Queen 4식 지휘 루프가 없다

- 위치·진형·대형이 전투 결과를 바꾸지 않는다.
- 분대 전환의 전술적 이유가 없다.
- 사기·피로는 표시용 수치에 가깝고 명령 선택과 연결되지 않는다.
- 구조는 거리·위험·시간 비용 없이 Space 한 번으로 즉시 처리된다.

### 4. 첫 플레이 경험이 비교 도구처럼 보인다

- 첫 화면의 제목과 문구가 `렌더러 선택 실험`, `테이블탑 렌더러 비교`다.
- 플레이어에게 목표, 제한 시간, 패배 조건, 분대 차이, 구조 의미를 설명하지 않는다.
- HUD가 FPS·p95·드로우콜 중심이라 게임 정보보다 개발 지표가 앞선다.
- 일시정지, 사운드, 설정, 피드백, 결과 요약과 다음 플레이 유도가 없다.

### 5. 콘텐츠가 한 장면에 머문다

- 하나의 75초 전투뿐이다.
- 적 종류·보스 행동·웨이브 변화·전장 장애물·런 진행이 없다.
- 100/200/300 선택은 난이도 설계가 아니라 renderer 부하 선택에 가깝다.

## 다음 구현 순서

1. 게임 정체성을 Three.js 2.5D + Phaser Canvas fallback으로 고정한다.
2. 이동·진형·구조가 생존 확률을 바꾸도록 전투 규칙을 다시 설계한다.
3. 처치 경험치, 짧은 레벨업 선택, 런 내 강화 3~5회를 추가한다.
4. 두 분대의 역할과 명령을 다르게 만들고 분대 전환에 전술적 이유를 부여한다.
5. 거리·시간·위험이 있는 구조 행동과 구조 보상을 만든다.
6. 60~90초 안에 도입→압박→절정→결과가 보이는 웨이브·보스를 만든다.
7. 비교 UI와 개발 HUD를 숨기고 게임 제목·목표·상태 HUD·결과 화면으로 교체한다.
8. 처음부터 끝까지 사람이 직접 플레이하는 E2E와 무입력/숙련 입력 결과 차이 테스트를 추가한다.

성능 비교는 위 핵심 루프가 완성된 뒤 다시 실행한다.
